# noob

Run `noob` in iTerm. A single loading screen appears immediately, then the complete dashboard replaces it. The footer counts down each second, and the data refreshes every 60 seconds; press Ctrl-C to stop. Press `s` to save a 1080 × 1350 PNG usage card to `~/Downloads`; each card gets a newly generated cyber-pixel avatar, and a green line at the bottom shows the exact saved path. The home card rereads platform usage and Codex quota when you press the key. Its 5H and WEEK footer bars show the remaining percentage with the same green, yellow, or red status as the terminal bars; a gray dash means quota data is unavailable. Press `m` to save a matching 1080 × 1350 reset card to `~/Downloads`; it fetches a fresh reset-credit snapshot and shows the available count and reported expiries in local time, up to 20 entries on one card. Press `k` to open the models view, which lists every model from every platform with today/week/month/all cost; click a column heading to sort that period descending, and click it again for ascending. Press `k` again to return to the home view. Pressing `s` on the models view saves a 1080 × 1350 models card with the full model list instead of the home card; the card keeps the column and direction you are currently sorted by, and marks that column with ↓ or ↑. If the fresh reset-credit query fails or the count is missing, no reset card is saved. All cards use the built-in macOS Quick Look and `sips` tools. Local spending estimates use the same API-price-equivalent rates as the terminal view. Quota bars always use the solid/outline parallelograms `▰` / `▱` (original design 15). Run `noob-shapes` to preview this bar. The home PLATFORMS view groups each platform (Codex, DeepSeek, and any future platform) inside a rounded box with the platform marker and its accent color — Codex uses the OpenAI green, DeepSeek its blue — showing its quota bars, per-period COST, and BALANCE, followed by an unboxed TOTAL block that combines every platform and shows cost and token totals. Run `noob --once` for one snapshot or when scripting. Requires the `codex` CLI and a ChatGPT/Codex login (`codex login`). No API key or Python packages are needed for the default view; set `DEEPSEEK_API_KEY` to add the optional DeepSeek balance line.

The top banner shows available Codex rate-limit reset credits and the expiration time for each available credit, when provided by the account response. It uses two lines on wide terminals and expands the times into separate lines on narrow terminals. It is captured once at startup and remains a launch-time snapshot during automatic refreshes. The quota section calls the official Codex app-server `account/rateLimits/read` method for usage percentages and reset timestamps. Its bars show the **remaining** percentage: green at 60% or more, yellow from 20% to below 60%, and red below 20%. The sea-green upward arrow below each bar marks an even-use pace: its position is the fraction of the window's time left until reset, so a 5-hour window with 40% of its time left points to about 40% remaining quota. It is a visual guide, not an official usage target. The Codex local source scans `~/.codex/sessions` (or `$CODEX_HOME/sessions`) and totals **increments** in `token_count` events, grouped by the `turn_context` model. It excludes `codex-auto-review` from local model rows and totals. It shows local-calendar-day, Monday-start week, month, and all-local-history token totals and hypothetical API-price-equivalent USD amounts for the total and each model. Cached input and output are priced separately. This is **not** the amount charged for your subscription, and logs from other devices or cloud runs are not included. The local log format is not a public billing API, so a future Codex update could require a parser change.

The dim renewal line inside the CODEX block of the PLATFORMS view shows the next ChatGPT Plus renewal date and elapsed days since the first subscription date. `subscription_info.json` stores the manually verified renewal date and the first subscription date (`started_on`) in `YYYY-MM-DD` format. The day count is the number of elapsed local calendar days since that first date and updates daily. After the recorded renewal date passes, the line says the renewal date is unverified instead of showing a stale date. The Codex rate-limit account response does not provide subscription billing dates.

The display refresh reads local files and performs one account-rate-limit query per minute; pressing `s` or `m` makes one additional account-rate-limit query for that image. The countdown itself makes no queries. It does not start a Codex turn or request a model response, so it does not consume model tokens. OpenAI does not publish a guarantee that unlimited automated polling is allowed; if the rate-limit query fails, `noob` shows a warning and retries on the next refresh.

Each launch (including `noob --once`) fetches model IDs and Standard API text prices from https://developers.openai.com/api/docs/pricing.md before calculating local usage. No API key is needed. The same table provides short- and long-context rates; long-context prices apply above 272K input tokens. A successful fetch is cached atomically in `pricing_cache.json` beside the program. If the network times out (8-second timeout) or the page format changes, noob uses the last valid cache, then built-in reference prices, and displays a dim fallback notice. Prices for retired models are retained for historical usage. The 60-second dashboard refresh and card export use the prices loaded at launch; restart noob to fetch newly published models. Only models with local usage appear in the dashboard. Unknown model IDs remain unpriced rather than receiving a guessed rate. Estimates exclude tool charges and other possible price adjustments and use the latest loaded prices for historical tokens, rather than historical billing rates.

Optional mode: `noob --api` also fetches the actual organization API bill if `OPENAI_ADMIN_KEY` is set. This is separate from the ChatGPT subscription and is not polled continuously. The old `--api-only` flag remains an alias.

Optional DeepSeek balance: set `DEEPSEEK_API_KEY` to show your DeepSeek account balance in the DEEPSEEK block of the PLATFORMS view (the amount is colored like other money in noob), and on the saved usage card just below its 5H/WEEK quota bars. noob calls `https://api.deepseek.com/user/balance` once per dashboard refresh (never when the key is unset, where the line instead reads `set DEEPSEEK_API_KEY`). The balance is shown in CNY (`¥110.00`); any non-CNY entry is converted at the live USD/CNY rate fetched once per launch from `https://api.frankfurter.app/latest?from=USD&to=CNY`, falling back to `1 USD = 7.1 CNY` when the rate cannot be fetched. The card shows the same value, or `—` when unavailable. If the balance query fails, the line reads unavailable and noob reports the reason in STATUS, then retries on the next refresh. This reads the public DeepSeek balance endpoint directly and is unrelated to the OpenAI/Codex data above.

The key is read from the `DEEPSEEK_API_KEY` environment variable first. If that is unset, noob falls back to the macOS Keychain and reads the generic password stored under the service name `noob-deepseek`. Store it once (the value is typed in your own terminal and never enters a config file), then restart noob:

```sh
security add-generic-password -s noob-deepseek -a "$USER" -w
```

The environment variable takes precedence when both are present, and the Keychain is only consulted at launch.

DeepSeek usage in the local tables: when the `opencode` CLI is on `PATH`, noob also reads DeepSeek usage from the local OpenCode server (`GET /api/experimental/session/stats`) and adds it as a DeepSeek block in the home PLATFORMS view and as model rows in the models view (`k`). Only models whose provider is `deepseek` are included. Tokens come from OpenCode's recorded `input` / `cache.read` / `cache.write` / `output` / `reasoning`, but the USD amount is **not** OpenCode's own cost. At launch noob fetches DeepSeek's live price table from `https://api-docs.deepseek.com/zh-cn/quick_start/pricing` (CNY per 1M tokens for cache-hit input, cache-miss input, and output, split into off-peak and peak) plus the USD/CNY rate, then prices the tokens itself. The DEEPSEEK block shows this in CNY; the TOTAL block and the models view convert it to USD at the live rate so every platform is comparable there. Cache writes are free. DeepSeek charges **double** during peak hours (01:00–04:00 and 06:00–10:00 UTC, Monday–Friday, excluding Chinese holidays), so noob re-queries OpenCode for each peak window and bills those tokens at the peak rate. If the price page or the FX rate cannot be fetched, noob falls back to its built-in table and rate. Because DeepSeek's model id (`deepseek-flash`) does not encode the version, noob also calls `GET https://api.deepseek.com/models` at launch and maintains `deepseek_models.json`, the history of each id's display name (for example `DeepSeek-V4.1-Flash`). When a name changes, usage is sliced at the recorded time so the new version appears as its own model row automatically. The boundary is dated by the first launch that observed the change, so a switch that happened while noob was not running is attributed to the earlier name, and the first ever run cannot reconstruct older versions. If `opencode` is not installed this source is skipped, and if the query fails noob shows a warning in STATUS. This is a separate source from the local Codex logs scanned above.

Pi usage in the local tables: noob also reads DeepSeek usage recorded by this coding agent (`pi`) from its own session logs under `~/.pi/agent/sessions` (or `$PI_CODING_AGENT_SESSION_DIR`, with `$PI_CODING_AGENT_DIR` overriding the config base). Each assistant message stores its token usage (`input` / `cacheRead` / `cacheWrite` / `output`), plus `reasoning` which is already part of `output` and is therefore not counted twice. Only messages whose provider is `deepseek` are included, and the model id is mapped through the same `deepseek_models.json` display-name history so pi rows merge with OpenCode rows under one model. The cost is **not** pi's own `cost.total`: pi prices every message at DeepSeek's standard rate, which is the peak column, so off-peak usage would be billed at double. Instead each message is priced from the same DeepSeek CNY table as the OpenCode path, using the message timestamp to select the peak or off-peak column exactly, and converted to USD at the live rate. This was verified against the DeepSeek console: 105 requests / 8,348,038 tokens reported ¥2.71, and the recomputed total was ¥2.70. The two sources are summed together before the DEEPSEEK block, the models view, and the TOTAL block are built. This is a separate source from the local Codex logs scanned above.

DeepSeek source split: under the DEEPSEEK block's COST line, noob shows two dimmed sub-rows breaking that cost into the `opencode` and `pi` sources (each in CNY, all four periods). The saved home card shows the same split as indented `opencode` / `pi` rows beneath the DEEPSEEK platform row.
